# Story Navigation 时间轴增强设计记录

## 1. 背景

调研中发现，短剧用户即使在内容节奏已经很快的情况下，仍有相当比例会使用倍速观看。这说明部分用户并不总是线性沉浸式消费短剧，而是存在更强的剧情定位需求：

```text
我想快速知道这集讲到哪了
我想跳过铺垫
我想直达关键剧情
我想补看某个重要段落
```

因此，可以在播放器中增加一个轻量的 `Story Navigation` 能力。它不是即时互动主功能，也不是完整章节页，而是帮助用户在短剧时间轴上理解剧情结构并快速定位。

## 2. 核心定位

`Story Navigation` 回答的问题是：

```text
这一集的剧情结构如何，用户现在拖到的位置大概在讲什么？
```

它与 `Expression Trigger` 的区别是：

```text
Story Navigation -> 用户想理解 / 定位 / 跳转的剧情段落
Expression Trigger -> 用户想即时表达的剧情时刻
```

之前“剧情转折点 = 用户表达点”的假设不适合即时互动，但剧情转折点、叙事阶段变化、冲突推进等信息非常适合做剧情导航。

## 3. 第一版范围

第一版只做时间轴增强，不做复杂交互。

包含：

- 在播放器进度条上显示剧情节点刻度；
- 用户拖动进度条时，显示当前位置对应的剧情标签；
- 用户拖到某个剧情节点附近时，可以看到短标题，例如“误会爆发”“女主反击”“身份揭露”；
- 点击或拖动到节点后，播放器跳转到对应时间。

不包含：

- 独立剧情地图页面；
- 半屏章节抽屉；
- 多级章节目录；
- 复杂剧情搜索；
- 自动跳过铺垫；
- 个性化跳转推荐；
- 把剧情导航做成比赛主功能。

## 4. 用户体验

时间轴增强应尽量复用播放器原有心智，不增加额外学习成本。

### 4.1 默认观看状态

默认状态下，进度条仍保持简洁，只显示少量剧情节点刻度。节点不应过密，避免让进度条变得杂乱。

建议一集短剧第一版控制在：

```text
3 到 6 个剧情节点
```

### 4.2 拖动进度条

用户拖动进度条时，在手指上方或进度条上方显示当前剧情段落标题。

示例：

```text
00:42 女主反击
```

如果当前位置位于两个节点之间，显示当前所属段落，而不是强行吸附到最近节点。

### 4.3 节点跳转

用户拖动或点击到某个节点附近时，可以跳转到该剧情节点的 `start_time`。

第一版不需要做复杂吸附动画，只要保证节点提示明确、跳转时间准确。

## 5. 算法产物

剧情导航需要的是 `Story Chapter` 或 `Story Segment`，而不是表达触发点。

建议第一版输出结构：

```json
{
  "chapter_id": "ch_demo_ep01_001",
  "video_id": "demo_ep01",
  "start_time": 0.0,
  "end_time": 18.4,
  "title": "开局设定",
  "summary": "女主醒来发现处境异常，故事冲突开始铺垫。",
  "chapter_type": "setup",
  "importance": 0.62
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `chapter_id` | 剧情段落 ID |
| `video_id` | 视频 ID |
| `start_time` | 段落开始时间，秒 |
| `end_time` | 段落结束时间，秒 |
| `title` | 时间轴上展示的短标题 |
| `summary` | 段落摘要，用于调试和后续展示 |
| `chapter_type` | 段落类型，例如 setup、conflict、reversal、climax、ending |
| `importance` | 重要度，0 到 1 |

第一版前端主要消费：

```text
start_time
end_time
title
importance
```

## 6. 识别方式

剧情导航可以比表达触发点更依赖剧情结构理解。

推荐输入：

- 字幕时间线；
- 视频关键帧；
- 视频标题和描述；
- 可选的镜头切分结果。

推荐流程：

```text
字幕 + 视频关键帧 + 元数据
  ↓
识别主要剧情阶段
  ↓
合并过短或过密段落
  ↓
生成 3 到 6 个时间轴节点
  ↓
输出 Story Chapter 列表
```

和 `Expression Trigger` 不同，剧情导航不需要判断用户是否有表达欲，因此不应使用“是否适合互动”作为主要标准。

## 7. 与主功能的关系

剧情导航是辅助能力，不是 DramePulse 的主打功能。

它补充主链路：

```text
内容理解 -> 剧情导航
内容理解 -> Expression Trigger -> 即时互动
```

两者可以共享视频、字幕、元数据和部分大模型能力，但产物应分开：

- `Story Chapter` 用于时间轴导航；
- `Expression Trigger` 用于即时表达互动；
- 不要把所有章节节点都当成互动触发点；
- 不要把所有互动触发点都强行展示为章节节点。

## 8. 非目标

第一版不做以下事情：

- 不做花哨剧情地图；
- 不做剧情搜索；
- 不做用户个性化导航；
- 不根据弹幕实时调整章节；
- 不替代短剧播放器的基础进度条；
- 不把章节标题做成长文摘要；
- 不让导航功能抢占即时互动主线。

## 9. 第一版验收标准

第一版只需要证明“剧情导航”作为轻量辅助功能成立：

1. 每集生成 3 到 6 个剧情节点；
2. 节点时间基本落在剧情阶段变化处；
3. 每个节点标题短、清楚、适合显示在进度条附近；
4. 拖动进度条时能看到当前位置剧情标签；
5. 点击或拖动到节点后能跳转到对应时间；
6. 不干扰视频观看和即时互动。
