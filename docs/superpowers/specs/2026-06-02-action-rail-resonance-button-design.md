# Action Rail 共鸣按钮交互设计

## 1. 核心判断

短剧高光互动不能只依赖“用户情绪强烈”。

更准确的表达链路是：

```text
强烈情绪产生
+ 用户知道自己的表达会进入公共空间或加入群体现场
-> 用户进行表达
-> 获得个人反馈和群体反馈
```

这也是弹幕、点赞、收藏等互动成立的原因。用户不是单纯想完成一个动作，而是知道自己的表达会被别人看见、会进入公共计数、会成为一场共同反应的一部分。

因此，情绪类互动如果只给本地特效，动机很弱。它必须在出现时就暴露公共性：

```text
这里已经有很多人爽到了
这里很多人都在笑
这里很多人都磕到了
这里很多人都泪目了
```

## 2. 方案定位

Action Rail 共鸣按钮是短剧高光点附近临时出现的右侧互动入口。

它不是弹幕，也不是投票，也不是普通点赞。它的目标是让用户用一次低摩擦动作加入当前剧情高光的公共情绪现场。

核心体验：

```text
剧情进入高光点
-> 右侧 action rail 顶部出现一个情绪共鸣按钮
-> 按钮下方显示已有参与人数
-> 用户点击或连点按钮
-> 按钮产生轻量反馈，人数跳动
-> 用户感知自己加入了这场公共情绪
```

它和现有两个候选交互的区别：

- 心里话弹幕：表达一句具体内容，进入弹幕公共空间；
- 情绪场：强调沉浸式情绪释放；
- Action Rail 共鸣按钮：强调加入右侧公开互动指标，像点赞一样自然。

## 3. 出现位置

第一版建议放在右侧 action rail 顶部，不替换原有按钮。

布局关系：

```text
右侧 action rail
  高光共鸣按钮
  点赞
  评论
  收藏/喜欢
  分享
```

选择原因：

- action rail 是短视频用户最熟悉的公开互动区域；
- 点赞、评论、分享本来就带人数，用户理解“这里是公共反馈”；
- 不遮挡底部标题、字幕和进度条；
- 不需要替换基础功能，避免用户困惑；
- 与情绪场、心里话弹幕形成清晰差异。

不建议第一版替换点赞、评论、分享按钮。高光互动是临时增强入口，基础互动是稳定播放器能力，二者不应互相抢占。

## 4. 组件形态

共鸣按钮保持 action rail 的纵向按钮语言：

```text
[情绪图标]
8.2万
```

情绪图标根据高光类型变化：

- 爽点：火焰、闪电、爆点；
- 笑点：笑脸；
- 甜点：心动、糖、爱心；
- 泪点：泪滴、纸巾、心碎。

人数文案第一版建议短，不写长句：

```text
8.2万
12.6万
3.4万
```

如果需要强化语义，可以在按钮出现时短暂显示小标签：

```text
8.2万人爽到了
```

标签只在出现初期展示，随后收敛为图标 + 数字，避免长期遮挡画面。

## 5. 用户动作

第一版只做点击和短时间连点，不做长按或复杂滑动。

原因：

- 和右侧 action rail 的既有使用方式一致；
- 不和上滑切视频、视频暂停、拖动进度冲突；
- 实现和调试成本低；
- 用户能立刻理解。

交互规则：

```text
点击一次 -> 加入共鸣
短时间连点 -> 强化个人释放感
一段高光内只记录一次真实参与
```

连点可以用于本地视觉反馈，但统计层第一版可以只记一次，避免把 demo 做成刷数。

## 6. 反馈设计

反馈需要同时表达两件事：

```text
我表达出去了
我加入了很多人的表达
```

建议反馈：

- 图标轻微放大回弹；
- 按钮外圈出现一圈短暂光环；
- 数字向上跳动或短暂 +1；
- 按钮周围释放少量粒子；
- 可选短文案：`已加入`、`你也爽到了`。

不要做大面积特效，不要遮挡剧情主体。它应该像点赞反馈一样轻，但比普通点赞更有高光情绪感。

## 7. 公共性前置

这个方案的关键不是按钮，而是按钮出现时就让用户知道：

```text
这里已经是一个公共情绪现场
```

因此人数必须在用户操作前可见，而不是点完后才出现。

错误设计：

```text
只出现一个情绪按钮
用户点击
播放一个本地特效
```

正确设计：

```text
出现情绪按钮 + 已参与人数
用户看到很多人已经加入
用户点击加入
人数和按钮即时反馈
```

如果没有人数或热度，它会退化成一个 emoji 按钮，动机不足。

## 8. 数据结构

第一版可以先使用前端本地 fixture，不强制接后端。

建议最小结构：

```ts
type ActionRailResonanceCue = {
  cueId: string;
  videoId: string;
  highlightId: string;
  triggerTime: number;
  durationSec: number;
  emotionType: "爽点" | "笑点" | "甜点" | "泪点";
  label: string;
  icon: string;
  baseCount: number;
  countText: string;
  feedbackText: string;
};
```

示例：

```json
{
  "cueId": "resonance_case1_ep01_001",
  "videoId": "case1_ep01",
  "highlightId": "h_case1_ep01_001",
  "triggerTime": 42.0,
  "durationSec": 6.0,
  "emotionType": "爽点",
  "label": "爽到了",
  "icon": "flame",
  "baseCount": 82000,
  "countText": "8.2万",
  "feedbackText": "你也爽到了"
}
```

## 9. 用户事件

第一版至少采集：

```text
exposure：按钮曝光
tap：用户点击
burst_tap：短时间多次点击
settle：反馈展示完成
dismiss：高光窗口结束未点击
```

事件字段建议：

```ts
type ActionRailResonanceEvent = {
  eventType: "resonance_exposure" | "resonance_tap" | "resonance_burst_tap" | "resonance_feedback_shown" | "resonance_dismiss";
  cueId: string;
  videoId: string;
  highlightId: string;
  emotionType: string;
  currentTime: number;
  tapCount?: number;
};
```

## 10. 交互状态

前端可以把共鸣按钮拆成以下状态：

```text
idle
-> visible
-> participating
-> feedback
-> completed
```

状态说明：

- `idle`：当前没有可展示的高光共鸣 cue；
- `visible`：按钮已在 action rail 顶部出现，人数和图标可见；
- `participating`：用户点击或短时间连点，按钮持续响应；
- `feedback`：展示一次加入反馈，例如数字跳动、光环、短文案；
- `completed`：当前 cue 已参与或展示结束，同一轮播放中不再重复出现。

如果用户完全不点击，cue 到达结束时间后进入 `completed` 或 `dismissed`。如果用户已经点击，按钮可以在短反馈后收起，也可以保留到高光窗口结束；第一版建议点击后反馈 `800ms` 到 `1200ms`，随后恢复普通 action rail，避免长期占用注意力。

## 11. 前端组件边界

这个方案应渲染在真实右侧 action rail 位置，而不是统一实验 overlay。

建议新增独立目录：

```text
apps/player-demo/src/action-rail-resonance/
  types.ts
  cues.ts
  scheduler.ts
  formatCount.ts
  ActionRailResonanceButton.tsx
```

职责划分：

- `types.ts`：定义 cue、状态和事件类型；
- `cues.ts`：第一版本地 demo cue；
- `scheduler.ts`：根据当前播放时间、seek reset 和 completed cue 找到可展示按钮；
- `formatCount.ts`：把数字转成 `8.2万` 这类短文案；
- `ActionRailResonanceButton.tsx`：渲染按钮、人数、点击反馈和本地计数跳动。

`PlayerActionRail` 负责在原有按钮列表顶部插入共鸣按钮。`PlayerPage` 只负责传入当前播放时间、视频 ID、seek reset 和当前交互模式，不承载按钮动画、计数或事件细节。

交互模式开关可以继续保留，但只控制是否启用这个候选方案，不决定它的渲染容器。正式交互应该待在各自天然的位置：

```text
情绪场 -> 视频窗口边缘
心里话弹幕 -> 弹幕输入入口旁边
Action Rail 共鸣按钮 -> 右侧 action rail 顶部
```

## 12. 与其他方案的关系

Action Rail 共鸣按钮可以作为第三个正式候选方案，与心里话弹幕和情绪场并列：

```text
心里话弹幕：具体内容表达
情绪场：沉浸式情绪释放
Action Rail 共鸣按钮：加入公共情绪计数
```

如果后续选择实现，它不应放在统一实验 overlay 容器里，而应进入 `PlayerActionRail` 或 action rail 上方的真实播放器 UI 层。

交互模式开关仍然可以保留，用于对比不同方案，但渲染位置必须是各方案真实应该出现的位置。

## 13. 验收标准

第一版完成后应满足：

1. 播放到配置的高光时间点时，右侧 action rail 顶部出现共鸣按钮；
2. 共鸣按钮不替换点赞、评论、收藏和分享等原有按钮；
3. 按钮出现时已经展示人数，用户操作前能感知公共性；
4. 不遮挡人物主体、字幕、底部标题、弹幕入口、进度条和底部 tab；
5. 用户点击后，图标、光环或数字有即时反馈；
6. 用户短时间连点时，反馈能连续响应，但统计层第一版只记录一次真实参与；
7. 用户不点击时，按钮在 cue 展示结束后自然消失；
8. 同一个 cue 完成或消失后不在同一轮播放中重复触发；
9. seek 回触发点之前后，cue 可按既有播放器重置规则重新触发；
10. 不破坏视频播放、暂停、seek、竖滑切集、普通弹幕、心里话弹幕和 Story Q&A；
11. 前端 typecheck 和相关测试通过。

## 14. 第一版边界

第一版只做：

- 本地固定 cue；
- 右侧 action rail 顶部临时按钮；
- 图标 + 人数；
- 点击反馈；
- 本地人数跳动；
- 行为事件可先在前端记录或打印。

第一版不做：

- 长按选择器；
- 多情绪选择；
- 复杂排行榜；
- 真正后端计数同步；
- 替换原有点赞/评论/分享按钮；
- 大面积视频特效。

## 15. 成功标准

这个方案成功的判断不是“按钮好不好看”，而是用户是否能立刻理解：

```text
这里已经有很多人在表达，我可以一键加入。
```

如果用户看到按钮只觉得“这是一个新 emoji”，方案就失败。

如果用户看到按钮觉得“这里已经有 8.2 万人爽到了，我也点一下”，方案才成立。
