# 情绪光场连点交互设计

## 1. 背景

当前分支主线是设计并实现前端的情绪抒发交互。我们重新审视后认为，短剧高光点里的多数基础情绪，例如爽点、笑点、甜点和泪点，并不适合优先做成投票。

原因是这类高光通常不是观点分歧，而是同向情绪的强弱释放。用户看到爽点、笑点、甜点或泪点时，往往不是想在多个选项里做判断，而是想快速表达“我也有这个感觉”。

第一版交互目标是：

- 不打断播放；
- 不要求用户读长文案或做选择；
- 不改变现有播放器主要操作习惯；
- 用统一、低学习成本的动作完成情绪抒发；
- 在比赛展示中形成比普通弹幕、评论、点赞更有记忆点的视觉体验。

## 2. 方案定位

第一版采用 **情绪光场 + 连点表达**。

系统在剧情高光点附近，根据高光类型在屏幕边缘渲染轻量情绪氛围。用户如果产生共鸣，可以连续点击屏幕。点击次数会被解释为情绪能量，并驱动画面上的情绪反馈。

核心规则：

```text
高光点附近出现情绪光场
-> 用户连续点击屏幕
-> 点击越多，情绪反馈越强
-> 停止点击后结算一次共鸣反馈
-> 光场和反馈自然消失，播放不中断
```

第一版不区分屏幕中心和边缘，也不引入上滑、长按、双指等更多手势。所有情绪类型都统一使用连点。

## 3. 情绪类型

第一版支持四类基础短剧情绪：

- `爽点`
- `笑点`
- `甜点 / 磕到了`
- `泪点`

四类情绪使用同一种交互动作，但视觉反馈不同。重点不是“换颜色”，而是让同一次连点在不同剧情里被翻译成不同的情绪质感。

### 3.1 爽点

用户心理：

```text
终于赢了、解气、反击、打脸、爽到了。
```

视觉方向：

- 红橙色边缘光；
- 短促冲击波；
- 点击时能量从边缘向画面内推进；
- 可带轻微画面震动感，但不要影响观看。

反馈文案示例：

```text
爽到了
你和 2.4 万人一起爽到了
```

### 3.2 笑点

用户心理：

```text
绷不住了、好笑、荒诞、反差萌。
```

视觉方向：

- 明亮但克制的黄色或暖白节奏波纹；
- 点击时出现轻微弹跳感；
- 小碎点向外散开；
- 动效可以更快，但不能幼稚或像贴纸礼物。

反馈文案示例：

```text
绷不住了
你和 1.8 万人一起笑出了声
```

### 3.3 甜点 / 磕到了

用户心理：

```text
暧昧、心动、拉扯、他们有戏、磕到了。
```

视觉方向：

- 粉白或暖粉色边缘淡光；
- 点击时像心跳一样轻微扩散；
- 局部出现细小柔光粒子；
- 整体要轻，不要做成直播礼物或满屏爱心。

反馈文案示例：

```text
磕到了
你和 3.1 万人一起磕到了
```

### 3.4 泪点

用户心理：

```text
破防、心疼、难受、陪角色撑过这一刻。
```

视觉方向：

- 蓝灰或银白色低饱和边缘光；
- 点击时出现慢速水纹或柔和扩散；
- 边缘可以短暂变暗再回亮；
- 点击反馈要沉一点，不能像爽点一样爆裂。

反馈文案示例：

```text
破防了
你和 1.2 万人一起破防了
```

## 4. 手势规则

播放器现有交互中，单击屏幕用于暂停或继续播放。情绪光场不能破坏这个基础控制。

第一版采用简单手势仲裁：

```text
非情绪窗口：
单击 = 暂停 / 播放

情绪窗口：
单击 = 暂停 / 播放
双击或连续点击 = 情绪表达

进入情绪表达后：
后续点击都计入情绪能量
停止点击约 400ms = 结算并退出本轮连点
```

技术实现上，情绪窗口内第一下点击需要短暂暂存。建议延迟范围为 `160ms` 到 `220ms`：

```text
第一下 tap 到达
-> 暂不立刻执行暂停
-> 如果延迟内没有第二下，执行暂停 / 播放
-> 如果第二下到达，取消暂停，进入情绪连点态，并计入 2 次点击
```

这会让情绪窗口内的单击暂停产生极短延迟，但只发生在高光互动窗口内，可接受。第一版不做中心区域和边缘区域的差异化规则。

## 5. 交互状态

前端可以把交互拆成以下状态：

```text
idle
-> aura_visible
-> tap_pending
-> tapping
-> settling
-> completed
```

状态说明：

- `idle`：没有可参与的情绪高光；
- `aura_visible`：高光情绪光场出现，等待用户参与；
- `tap_pending`：第一下点击已发生，等待判断是单击暂停还是连点表达；
- `tapping`：用户已进入连点表达，持续累积情绪能量；
- `settling`：用户停止点击后展示本轮反馈；
- `completed`：当前高光本轮互动结束，不再重复触发。

同一个高光点在一次连续播放过程中只触发一次。后续如果用户 seek 回触发时间之前，可以重新允许触发，这一规则可沿用现有 Interaction Lab 的 reset 逻辑。

## 6. 数据输入

第一版前端可以先使用本地配置或 fixture 驱动，不要求立即改动后端契约。

建议最小数据结构：

```ts
type EmotionAuraType = "爽点" | "笑点" | "甜点" | "泪点";

type EmotionAuraCue = {
  cueId: string;
  videoId: string;
  highlightId: string;
  triggerTime: number;
  durationSec: number;
  emotionType: EmotionAuraType;
  label: string;
  resonanceText: string;
};
```

示例：

```json
{
  "cueId": "aura_case1_ep01_001",
  "videoId": "case1_ep01",
  "highlightId": "h_case1_ep01_001",
  "triggerTime": 38.0,
  "durationSec": 5.0,
  "emotionType": "爽点",
  "label": "爽到了",
  "resonanceText": "你和 2.4 万人一起爽到了"
}
```

后续如果要接入后端，可以把它作为 `Interaction Plan` 的新类型，例如 `emotion_aura_tap`。第一版先不强行修改共享 schema，避免在交互还未验证前扩大契约变更。

## 7. 事件采集

第一版至少应在前端本地记录以下事件。是否立即上报后端可以在实现阶段决定。

```text
emotion_aura_exposure
emotion_aura_tap_start
emotion_aura_tap
emotion_aura_settle
emotion_aura_dismiss
```

事件关键字段：

- `video_id`
- `highlight_id`
- `cue_id`
- `emotion_type`
- `client_time`
- `tap_count`
- `energy_level`
- `timestamp`

`energy_level` 可由点击次数映射得到，例如：

```text
1-2 taps: low
3-6 taps: medium
7+ taps: high
```

## 8. 前端组件边界

建议新增独立的 emotion aura 目录，避免继续把正式交互混进 Interaction Lab example：

```text
apps/player-demo/src/emotion-aura/
  types.ts
  cues.ts
  scheduler.ts
  tapGesture.ts
  EmotionAuraLayer.tsx
  EmotionAuraFeedback.tsx
```

职责划分：

- `types.ts`：定义情绪光场 cue、状态和事件类型；
- `cues.ts`：第一版本地 demo cue；
- `scheduler.ts`：根据当前播放时间找到可展示 cue；
- `tapGesture.ts`：实现单击暂停与连点表达的手势仲裁；
- `EmotionAuraLayer.tsx`：渲染边缘光场、连点反馈和结算态；
- `EmotionAuraFeedback.tsx`：按情绪类型渲染不同反馈质感。

`PlayerPage` 只负责传入当前播放时间、播放状态、点击事件入口和播放暂停回调，不承载具体动效逻辑。

## 9. 验收标准

第一版完成后应满足：

1. 播放到配置的高光时间点时，屏幕出现对应情绪光场；
2. 情绪光场不遮挡人物主体、字幕、右侧操作栏和底部剧情信息；
3. 非情绪窗口内，单击仍然暂停或继续播放；
4. 情绪窗口内，单击仍然暂停或继续播放；
5. 情绪窗口内，连续点击会进入情绪表达，不触发暂停；
6. 连点过程中，点击次数会驱动画面反馈增强；
7. 停止点击约 400ms 后展示一次共鸣反馈；
8. 爽点、笑点、甜点、泪点在视觉质感上可区分；
9. 同一个 cue 完成后不会在同一轮播放中反复弹出；
10. seek 回触发点之前后，cue 可按既有播放器重置规则重新触发；
11. 不破坏视频播放、暂停、seek、竖滑切集、普通弹幕和 Story Q&A；
12. 前端 typecheck 和相关测试通过。

## 10. 非目标

第一版不做：

- 投票选项；
- 弹幕发送；
- 长按、上滑、双指捏合等额外手势；
- 中心区域和边缘区域的差异化点击规则；
- 复杂个性化策略；
- 后端 schema 强制迁移；
- 满屏礼物特效；
- 影响剧情播放节奏的弹窗或暂停式互动。

## 11. 后续扩展

如果第一版验证有效，后续可以继续探索：

- 将情绪光场 cue 接入后端 `Interaction Plan`；
- 将 `tap_count` 和 `energy_level` 上报到后端用于高光评分；
- 在结算态后追加一句 AI 生成的“心里话”，允许用户轻推发送；
- 根据高光类型自动选择更细的视觉模板；
- 在答辩 debug 面板中展示识别到的高光类型、触发时间和用户情绪能量。
