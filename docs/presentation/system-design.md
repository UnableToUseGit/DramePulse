# DramePulse 系统设计

## 1. 设计目标

DramePulse 的系统设计目标是支撑一条完整闭环：

```text
内容/字幕/弹幕
  -> 高光资产
  -> 互动方案
  -> 播放器内互动
  -> 用户事件
  -> 统计结果与策略更新
```

本文档只讨论系统 level 的架构设计、层级交互和技术选型，不展开每个模块的内部实现。模块级细节放在 `module-designs/` 目录下。

## 2. 总体架构

系统分为三层：

- 体验层：负责播放器渲染、即时互动 UI 和用户行为采集；
- 业务层：负责高光识别、互动方案生成、行为统计和策略更新；
- 数据层：负责视频、字幕、弹幕、高光资产、互动方案、用户事件和统计结果的持久化。

三层之间通过三个核心对象串联：

- `Highlight Asset`：回答“哪里值得互动”；
- `Interaction Plan`：回答“如何互动”；
- `User Event`：回答“用户如何反馈”。

## 3. 系统闭环

```text
短剧视频/字幕/弹幕
  -> 高光点识别 pipeline
  -> Highlight Asset
  -> 互动方案生成 pipeline
  -> Interaction Plan
  -> FastAPI 后端下发
  -> Expo 播放器触发互动
  -> 用户点击或关闭
  -> User Event 上报
  -> 后端统计互动结果
  -> 规则策略更新
```

## 4. 技术选型概览

| 模块 | 技术选型 | 说明 |
| --- | --- | --- |
| 移动端播放器 | React Native + Expo | 适合快速实现 iOS/Android 真机演示 |
| 后端服务 | FastAPI | 接口开发快，适合 MVP 和演示部署 |
| 本地存储 | SQLite | 支撑本地开发、演示和离线样例数据 |
| 云端存储 | MySQL/OSS/CDN | 用于公网 API、视频资源和后续部署扩展 |
| 数据契约 | JSON Schema | 约束 Highlight Asset、Interaction Plan、User Event |
| 高光识别 | 字幕 + 视频帧 + LLM | 用少量样例快速形成可解释高光资产 |
| 互动生成 | LLM + 规则校验 | 生成贴合剧情的弹幕投票，并通过规则兜底 |

## 5. 主要流程图

### 5.1 高光资产生成流程

```text
视频/字幕/弹幕
  -> 抽帧和字幕整理
  -> 多模态 LLM 识别高光点
  -> JSON 结构化输出
  -> Schema 校验
  -> 人工复核
  -> Highlight Asset 入库
```

### 5.2 互动方案下发流程

```text
Highlight Asset
  -> 读取高光上下文
  -> 生成投票问题和选项
  -> 规则补全 ID、时间和状态
  -> Schema 校验
  -> Interaction Plan 入库
  -> 播放器通过 API 拉取
```

### 5.3 播放器互动流程

```text
播放器加载视频
  -> 拉取弹幕和互动方案
  -> 播放时间进入 trigger_time
  -> 展示弹幕投票
  -> 用户点击选项
  -> 展示比例反馈
  -> 上报 User Event
```

### 5.4 反馈统计流程

```text
User Event
  -> 后端接收事件
  -> 写入事件表
  -> 聚合曝光、点击、关闭和选项分布
  -> 返回互动结果
  -> 更新高光分数和互动策略
```

## 6. 系统边界

MVP 阶段聚焦短剧高光互动闭环，不扩展完整用户账号、推荐系统、评论社区、支付、电商交易或复杂个性化画像。

系统设计保留扩展空间，但当前实现优先保证演示链路清晰、接口稳定、数据契约可解释。
