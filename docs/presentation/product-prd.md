# DramePulse 产品 PRD

## 1. 项目背景

短剧是典型的移动端高频内容消费场景。相比传统长视频，短剧单集时长更短，剧情节奏更快，冲突、反转、爽点、误会、甜宠和情绪爆发更加密集。

用户在观看短剧时，经常会在剧情高光瞬间产生即时表达欲，例如：

- 看到打脸反杀时想表达“爽到了”；
- 看到身份揭露时想表达“反转了”；
- 看到虐心桥段时想表达“心疼女主”；
- 看到甜蜜互动时想表达“磕到了”；
- 看到关键剧情时想表达自己的判断或站队。

当前常见短剧产品主要依赖弹幕和评论承载用户表达。弹幕和评论可以提供表达空间，但它们都存在一个共同问题：用户需要主动进入表达入口，并输入或选择内容。这和短剧“剧情推进快、情绪窗口短”的观看节奏天然冲突。

DramePulse 的核心问题是：

```text
当用户在短剧高光点产生表达欲时，系统能否主动给出低摩擦互动入口，让用户不打断观看也能完成情绪或观点表达？
```

## 2. 用户痛点

### 2.1 表达摩擦高

传统弹幕和评论需要用户完成“点击入口 -> 输入文字 -> 发送”等动作。对短剧观看场景来说，这个链路过长。用户还没完成输入，剧情可能已经进入下一段。

### 2.2 打断观看体验

短剧的爽感和沉浸感依赖连续观看。弹幕输入、评论区展开、回复等操作都会让用户从剧情中脱离，尤其在竖屏移动端上，输入框和键盘会明显遮挡播放区域。

### 2.3 反馈不够即时

用户发出弹幕或评论后，通常无法立刻获得共鸣反馈。点赞、回复和评论互动往往滞后发生，不能服务于“刚刚那个高光瞬间”的情绪强化。

### 2.4 高光点没有被系统化利用

短剧内容中存在大量适合互动的高光片段，但常规播放器只是线性播放内容，没有把高光点转化为可运营、可下发、可评估的互动资产。

## 3. 产品定位

DramePulse 是一套面向移动端短剧消费场景的即时互动激发系统。

它不是泛视频 App、评论系统、弹幕系统或推荐系统，而是围绕短剧高光点建立一条可展示、可验证、可扩展的互动闭环：

```text
内容/字幕/弹幕
  -> 高光资产 Highlight Asset
  -> 互动方案 Interaction Plan
  -> 播放器内低摩擦互动
  -> 用户事件 User Event
  -> 统计结果与策略更新
```

产品的核心价值包括：

- 对用户：降低表达门槛，不打断播放，也能在高光点表达情绪或观点；
- 对内容：把剧情高光点结构化，形成可复用的互动资产；
- 对平台：通过用户反馈衡量高光点和互动方案质量，为后续策略优化提供依据；
- 对比赛展示：用客户端、服务端、算法 pipeline 和数据契约构成完整工程闭环。

## 4. 目标用户与场景

### 4.1 目标用户

目标用户是移动端短剧观看用户，尤其是习惯竖屏刷剧、追求剧情爽感和即时共鸣的用户。

这类用户的典型特征是：

- 单次观看时长碎片化；
- 对剧情反转、冲突和情绪刺激敏感；
- 愿意用简单动作表达态度；
- 不愿为了表达而中断观看；
- 更容易被“其他观众也这么想”的反馈强化参与感。

### 4.2 核心场景

用户正在手机端观看一集短剧。当剧情进入高光点，例如身份揭露、打脸反杀、甜蜜撒糖或冲突爆发时，播放器自动展示一个轻量互动入口。

用户无需输入文字，只需点击一个选项，就能完成表达。点击后，系统立即展示比例反馈或共鸣反馈，让用户知道自己和多少观众做出了相同选择。

核心用户旅程为：

```text
观看短剧
  -> 播放到剧情高光点
  -> 系统自动出现互动入口
  -> 用户点击表达情绪或观点
  -> 系统展示即时反馈
  -> 用户行为回传后台
  -> 后台更新统计和互动策略
```

## 5. 产品目标

### 5.1 MVP 目标

MVP 阶段目标是完成从内容理解到播放器互动，再到用户反馈采集的最小闭环。

MVP 必须包含：

- 短剧列表和基础播放能力；
- 高光点识别、标注或导入能力；
- 高光点和互动方案的结构化存储；
- 播放器在指定高光时间自动触发互动；
- 用户以低摩擦方式完成表达；
- 用户点击后获得即时反馈；
- 用户事件回传后台；
- 后台提供互动结果或统计查询能力。

MVP 的成功标准不是互动形式数量，而是闭环是否完整：

```text
哪里值得互动
  -> 如何互动
  -> 端上是否触发
  -> 用户是否反馈
  -> 反馈是否被记录和统计
```

### 5.2 优秀展示目标

在完成 MVP 的基础上，DramePulse 需要进一步证明系统具备真实业务基础设施的潜力。

优秀展示目标包括：

- 高光点识别过程可解释，能说明为什么某个片段适合互动；
- 互动方案贴合剧情，而不是通用问卷；
- 播放器体验接近真实短剧观看场景；
- 事件和统计链路清楚，能支撑策略更新；
- 技术文档完整，能说明模块边界、技术选型和扩展方式；
- 演示链路稳定，适合答辩时实机展示。

### 5.3 创新探索目标

赛题鼓励在基础互动之外做自由探索。DramePulse 的创新方向主要围绕“情绪表达”和“观点表达”的结合。

在短剧场景中，用户不只想表达情绪，也可能想表达观点。例如：

- 女主该不该原谅男主；
- 这一幕到底谁更有道理；
- 用户更支持哪条剧情走向；
- 用户是否想让角色做出更强烈的反击。

因此，DramePulse 的互动方案不局限于“爽”“哭”“磕到了”等情绪按钮，也可以扩展为剧情站队、轻量投票、角色态度选择和剧情 Q&A。

## 6. MVP 功能范围

### 6.1 短剧列表与播放

播放器需要提供基础短剧观看能力：

- 展示可播放短剧列表；
- 进入竖屏播放页；
- 支持播放、暂停和进度控制；
- 支持普通弹幕展示；
- 支持上下滑切换剧集或视频；
- 在播放过程中持续感知当前时间。

该能力是所有即时互动的承载容器。

### 6.2 高光点识别与管理

系统需要识别或导入适合触发互动的剧情高光点，并将其结构化为 `Highlight Asset`。

高光点至少需要包含：

- 所属视频；
- 开始时间和结束时间；
- 高光类型；
- 主要情绪；
- 情绪强度；
- 剧情摘要；
- 触发互动的原因；
- 置信度或人工确认状态。

MVP 阶段可以使用“字幕 + 视频帧 + LLM 结构化抽取 + 人工校验”的方式完成识别。

### 6.3 互动方案生成

系统需要根据高光点生成前端可渲染的 `Interaction Plan`。

MVP 主交互形式为弹幕投票：

```text
这波反转你怎么看？  [爽到了] [太离谱了] [再看一遍]
```

互动方案至少需要包含：

- 互动 ID；
- 对应高光点 ID；
- 触发时间；
- 互动类型；
- 问题文案；
- 2 到 3 个选项；
- 点击后的反馈规则；
- 展示位置和状态。

### 6.4 播放器内即时互动

播放器在播放到高光点时自动展示互动组件。

交互原则：

- 不暂停播放；
- 不要求输入文字；
- 不遮挡人物、字幕和剧情关键区域；
- 优先使用点击完成表达；
- 点击后立即给出反馈；
- 互动组件展示时间短，避免长期占用屏幕。

### 6.5 用户事件采集

系统需要记录用户在播放和互动中的关键行为。

MVP 重点事件包括：

- 互动曝光；
- 选项点击；
- 反馈展示；
- 互动自然消失；
- 播放、暂停、拖拽、回看等播放行为。

这些事件会回传后台，用于统计互动效果和后续策略更新。

### 6.6 统计结果与策略更新

后台需要基于用户事件提供互动结果查询，例如某个选项的点击数、点击比例和总曝光量。

MVP 阶段策略更新可以采用简单规则：

- 点击率高的互动方案优先保留；
- 关闭率高或无人点击的互动方案降低优先级；
- 高反馈高光点提升 `highlight_score`；
- 低反馈高光点进入人工复核或替换互动方案。

## 7. 非目标范围

MVP 阶段不主动扩展以下能力：

- 完整用户账号系统；
- 大规模推荐系统；
- 完整评论社区；
- 支付、电商或广告交易系统；
- 实时流处理；
- 复杂个性化用户画像；
- 原生移动端 App 安装包；
- 多轮在线训练或复杂机器学习策略。

这些能力不是赛题 MVP 的核心，也会稀释“高光互动闭环”的展示重点。

## 8. 核心交互方案

### 8.1 弹幕投票

弹幕投票是 DramePulse MVP 的主交互形式。

它把传统弹幕的“共鸣感”和投票的“低摩擦”结合起来：系统在剧情高光点自动抛出一个贴合剧情的问题，用户通过点击 2 到 3 个选项完成表达。

示例：

```text
这一幕爽不爽？  [太争气了] [爽到了]
```

点击后展示：

```text
你和 68% 的观众一样选择了「爽到了」
```

选择弹幕投票作为 MVP 主交互，是因为它满足四个条件：

- 学习成本低，用户不需要理解新规则；
- 操作成本低，只需要一次点击；
- 表达能力强，可以表达情绪，也可以表达观点；
- 反馈直接，可以用比例和共鸣文案强化参与感。

### 8.2 Story Q&A

Story Q&A 是当前系统中的扩展能力，用于补充短剧观看过程中的剧情理解和问答体验。

它不替代弹幕投票，也不是 MVP 主交互，而是展示系统可以围绕剧情内容做更多互动扩展，例如：

- 用户询问角色关系；
- 用户询问前情提要；
- 用户询问某段剧情原因；
- 用户基于当前剧情继续探索。

## 9. 端到端验收标准

产品侧验收标准如下：

1. 用户可以看到短剧列表并进入播放页；
2. 播放器可以正常播放短剧，并展示基础弹幕；
3. 系统中存在结构化高光点数据；
4. 系统中存在与高光点关联的互动方案；
5. 播放到指定时间时，互动组件自动出现；
6. 用户点击选项后，播放器立即展示反馈；
7. 前端向后端上报互动事件；
8. 后端可以查询互动结果或统计；
9. 文档能够说明高光点、互动方案和用户事件如何组成闭环；
10. 演示过程不依赖临时解释，评委可以通过画面理解产品价值。

## 10. 产品边界与后续规划

DramePulse 当前阶段优先完成比赛可展示的完整闭环，而不是追求完整商业化 App。

后续可以继续扩展的方向包括：

- 更多互动形态：长按情绪光环、内心弹幕、角色站队、剧情 QTE；
- 更强的高光识别：引入多集上下文、角色关系和镜头节奏；
- 更完整的策略更新：基于曝光、点击、关闭、回看行为调整互动方案；
- 更丰富的数据看板：展示高光点效果、互动转化和用户反馈；
- 更真实的部署形态：云端数据库、对象存储、CDN 和移动端安装包。

这些扩展都围绕同一个产品核心展开：让短剧高光点从“只能被观看的剧情片段”变成“可以被表达、反馈和持续优化的互动资产”。
