# 业务层模块设计

## 1. 模块定位

业务层负责 DramePulse 的核心逻辑：识别哪里值得互动、生成如何互动的方案、统计用户反馈，并基于反馈更新策略。

业务层不负责前端 UI 渲染，也不直接管理视频播放器状态。

## 2. 子模块

### 2.1 高光点识别

输入视频、字幕和弹幕上下文，通过字幕整理、视频抽帧和 LLM 结构化抽取，输出 `Highlight Asset`。

### 2.2 互动方案生成

输入 `Highlight Asset` 和高光点附近上下文，生成 `Interaction Plan`。MVP 阶段主互动类型为 `danmaku_poll`。

### 2.3 行为统计

接收用户事件后，聚合互动曝光量、点击量、选项点击分布、点击率和关闭率。

### 2.4 策略更新

MVP 阶段采用简单规则更新高光分数和互动优先级。例如点击率高的互动方案保留，关闭率高的方案降权。

### 2.5 Story Q&A

作为扩展能力，支持用户围绕剧情内容提问，用于展示系统对短剧语义内容的进一步利用。

## 3. 输入输出

输入：

- 视频文件；
- 字幕文件；
- 弹幕数据；
- 用户事件；
- 历史统计。

输出：

- `Highlight Asset`；
- `Interaction Plan`；
- 互动统计结果；
- 策略更新结果。

## 4. 当前实现草稿

当前仓库已有高光识别 pipeline、互动方案生成 pipeline、FastAPI 互动方案读取接口、用户事件接口和互动结果查询接口。

后续需要补充算法 prompt 约束、fallback 规则、统计口径和策略更新示例。
